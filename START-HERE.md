# Core Defense — Cloudflare setup

## Deploy as a NEW app

1. Create a GitHub repository named `tower-defense`.
2. Extract this ZIP. Upload its contents directly into the repository root:
   `package.json`, `package-lock.json`, `wrangler.jsonc`, and the folders beside them.
   Do not upload the ZIP itself or put everything inside an extra parent folder.
3. Cloudflare → Workers & Pages → Create → Import a repository. Select this repo.
4. Worker name: **tower-defense**
5. Build command: `npm run build`
6. Deploy command: `npx wrangler deploy --config wrangler.jsonc`
7. Deploy. The SQLite Durable Object migration creates player storage automatically.
   No D1 database, R2 bucket, or secret needs to be created.
8. Open the provided workers.dev URL and choose a player name.
9. Optional custom domain: Worker → Domains & Routes → Add → Custom domain →
   `tower.cl1p.xyz` (the cl1p.xyz zone must be in your Cloudflare account).

A player link such as `https://tower.cl1p.xyz/adam` holds that player's saved game.
Use the same URL on another device. Return to an active wave and it starts paused.
This is a new app: do not replace Sudoku, Chat, or Mine Descent with these files.

## Playing

- Three sectors: The Outpost, Red Canyon, The Foundry.
- Complete all 12 waves in a sector to unlock the next.
- Tap Pulse, Mortar or Cryo, then an empty circular pad to build.
- Tap a tower for its range, upgrade (three levels total), or sell (70% refund).
- Start each wave yourself. Build and upgrade during waves too.
- Boss every fourth wave. Scouts, runners and armored enemies need different tactics.
- Pulse fires quickly; Mortar deals splash damage and ignores armor; Cryo slows.
- Core integrity is 20. Regular leaks cost one, tanks two, bosses five.
- Pause, 2× speed and optional synthesized sound are included. Sound starts off.
- New run/retry starts that sector over; unlocked sectors and best waves remain.
- Keyboard: focus the battlefield, arrow keys select a pad, Enter builds/selects.

## Saves and privacy

Cloud saves happen after purchases, waves and approximately every eight seconds
while fighting. The current snapshot includes enemies, towers and projectiles.
Backgrounding the page pauses it. A local backup helps with network interruptions;
keep that browser/device until cloud saving recovers. No offline cache is included,
so an initial page load still requires a connection.

The app detects conflicting saves from another tab/device and loads the newer
server state instead of silently overwriting it. Do not play the same link on two
devices simultaneously. Anyone with a link can play and replace that saved run.
Choose a unique link. This is a casual game, not an authenticated account system.
Simulation runs on the client. Saves are validated for shape and limits, but are
not cheat-proof; there is intentionally no competitive public leaderboard.

## Development

- `npm ci`
- `npm run build`
- `npm test` — deterministic combat and save tests
- `node tests/balance.mjs` — completes all three sectors with a test strategy
- `node tests/runtime.mjs` — Miniflare storage and routing integration
- `node tests/ui.mjs` — UI harness; requires optional `@napi-rs/canvas` for rendering

Runtime test can use MINIFLARE_MODULE to point to another installed Miniflare.
UI harness uses a mocked DOM and the actual Canvas rendering code; it does not
replace testing touch, sizing, and audio on a real phone.

No external assets, fonts, advertising, analytics, music files or CDN libraries
are loaded at runtime. Artwork and sound are drawn/generated by the game.
